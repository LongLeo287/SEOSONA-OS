# Karpathy Coding Standards

## Operating Standard

Write simple, inspectable code before clever code. Prefer a small deterministic implementation that can be verified by tests and command output.

## Rules

- Read the existing code before editing.
- Keep changes scoped to the task.
- Prefer plain data structures and explicit control flow.
- Add abstraction only when it removes real duplication or clarifies ownership.
- Use structured parsers for structured data.
- Keep comments rare and useful.
- Verify with the narrowest command that proves the claim, then broaden validation when shared behavior changes.
