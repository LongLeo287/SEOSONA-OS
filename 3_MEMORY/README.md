# 💾 3_MEMORY: The Spatial Memory System

**[English]**  
`3_MEMORY` is the persistent storage layer for SEOSONA OS. Because LLMs lack persistent memory across different chat sessions, this directory serves as the system's "MemPalace." It stores project states, error logs, architectural specs, and session exports to ensure continuous learning and continuity across tasks.

**[Tiếng Việt]**  
`3_MEMORY` là lớp lưu trữ dài hạn của SEOSONA OS. Vì các AI không có trí nhớ liên tục qua các phiên trò chuyện khác nhau, thư mục này đóng vai trò như một "Lâu Đài Ký Ức" (MemPalace). Nó lưu giữ trạng thái dự án, nhật ký lỗi, tài liệu kiến trúc và các bản báo cáo xuất ra để đảm bảo AI học hỏi liên tục và không bị mất ngữ cảnh.

---

## 📂 Structure / Cấu trúc

- 📁 **`projects/`**: Project-scoped memory namespaces. When a workspace connects to SEOSONA, a folder is created here to hold context, tasks, and history exclusively for that project.
- 📐 **`specs/`**: Technical specifications and architectural blueprints. Agents read these before making major changes to existing codebases.
- 🐛 **`errors/`**: Error logs, debugging notes, and post-mortem analyses. Essential for the OS's "Fix Loop" mechanism.
- 📜 **`logs/`**: Chronological audit trails and transcript logs.
- 📊 **`seo_exports/`**: The default output directory for data generated by the SEOSONA Audit module (CSVs, JSONs, HTML Dashboards).
- 📥 **`ingestion_zone/`**: A staging area for temporary data before it gets processed into `2_KNOWLEDGE`.

## 🚨 Core Rules / Quy tắc Cốt lõi

1. **State Persistence:** Always record critical decisions, bug solutions, or major architectural shifts into `specs/` or `errors/`. This prevents future agents from repeating the same mistakes.
2. **Project Isolation:** Do not mix context. Context for "Project A" strictly belongs in `projects/Project_A/`, protecting it from leaking into other projects.
3. **No Code Files:** Do not store actual execution scripts here. This is a passive storage system for knowledge states, not a logic engine.
